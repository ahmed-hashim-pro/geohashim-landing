tsz

A Rust library and command-line tool that compresses time series of (i64, f64) points without losing a single bit. For each block of 4,096 points it measures Gorilla, Chimp, Chimp128 and a decimal codec, and writes whichever is smallest.

Gorilla, the usual starting point, XORs each value with the one before and stores the bits that changed. That works when neighbouring floats share most of their bits. Most metrics reach a database as text, though: a tide gauge prints 1.327, and parsed to a double that is a repeating binary fraction. On five of the six real series here, Gorilla comes out bigger than gzip of the CSV. tsz checks, bit for bit, whether a block's values were printed decimals, and if so stores the integers.

1Read the text, keep the exact bits

tsz encode reads one timestamp,value per line, from a file or stdin. Timestamps are integers in any unit. A value is anything Rust's f64 parser accepts, or 0x and 16 hex digits for an exact bit pattern.

  • From here on a value is its 64 bits, not a number. -0 keeps its sign, and a NaN keeps its payload.
  • tsz decode --bits prints the 0x form back, so even a NaN payload survives a trip through text.
  • Bad input names the file and the line, and exits 2. Nothing is guessed or skipped, apart from one header line.

2Gorilla: XOR with the value before

Gorilla, from Facebook's in-memory time-series database, XORs each value with the previous one. A repeat costs one bit. Otherwise it stores the run of bits between the leading and trailing zeros, reusing the last window when the new bits fit inside it.

  • Timestamps store the delta of the delta. A steady scrape costs one bit per point.
  • Two changes from the paper, so that every i64 sequence round-trips: a fifth bucket for a full 64-bit jump, and wrapping arithmetic, so i64::MIN can sit next to i64::MAX.
  • The values follow the paper exactly. Within 2% of the existing tsz crate's size on five datasets is some evidence that both do.

A printed decimal is the problem. 1.327 and 1.297 differ in a few digits, but as doubles their XOR has bits set almost all the way down.

3Chimp and Chimp128: spend the bits differently

Chimp (VLDB 2022) noticed that XORs of real values rarely have many trailing zeros. It pays for a trailing-zero count only when there are more than six, and rounds the leading-zero count to one of eight values so it fits in three bits.

  • Chimp128 also lets each value pick its reference from the previous 128, through a table keyed on the low 14 bits. An exact repeat costs 9 bits.
  • Sensors revisit the same readings, so on the five sensor series Chimp128 is 45 to 66% smaller than Gorilla.
  • Both follow the paper's flag layout. A test pins the papers' costs: a constant series is exactly 1, 2 and 9 bits per value under Gorilla, Chimp and Chimp128.

On the Wikipedia counts Gorilla beats both. They are integers stored as floats, so their XORs end in long runs of zeros, and Chimp pays 11 bits of header where Gorilla usually reuses its window for 2.

4Decimal: check that every value was printed

For d from 0 to 15, the encoder tries n = round(v × 10d) on every value in the block. It keeps the first d for which n / 10d is the same 64 bits as v. Division and parsing are both correctly rounded, so 1327 / 1000 is exactly the double that "1.327" parses to.

  • Comparing bits, not values, is what keeps it lossless. -0.0 and NaN never match, and neither does a computed value such as 0.1 + 0.2.
  • The integers go to an adaptive code: first or second differences, zigzagged, with two bucket widths fitted to the block from all 2,016 pairs.
  • The same integer code competes for the timestamps, so gaps and irregular clocks get fitted widths too.

One value that doesn't fit sends the whole block to a float codec. There are no per-value exceptions, which pco and ALP have and this doesn't.

5Auto: measure every codec, write the cheapest

Every encoder is generic over a bit sink. auto runs each candidate into a counter that only adds up lengths, and writes only the cheapest. Blocks are independent, so each one chooses its timestamp codec and its value codec on its own.

  • The counter gives up as soon as it passes the best size so far. Decimal goes first, so the float codecs usually stop early. That took auto from about 17 to about 26 million points a second on encode, by the README's measurement.
  • Ties go to the earlier candidate, so the same input always gives the same bytes. A test hashes the bytes every codec writes for a fixed series.
  • Because auto chooses from a superset of what each fixed codec uses, it is never bigger than any of them. The property tests check that on every random series.

Bit for bitAbove this line tsz chooses how to store each block. Below it, what comes back must be the same 64 bits that went in, and bytes from anywhere are read as if they were hostile.

6Decode untrusted bytes without panicking

The format is a magic number, then blocks of a point count, one codec byte and two length-prefixed bit streams, then a zero. The decoder checks every one of those against what the encoder could have written, and a mismatch is an error, never a panic.

  • A header claiming a block of more than 220 points is refused before anything is allocated.
  • Every truncation of a valid stream must be an error. The tests cut 300 streams at every byte, flip bits in 2,000, and append random bytes after the magic 20,000 times.
  • Two cargo-fuzz targets run in CI on every push: arbitrary bytes into the decoder, and arbitrary series through every codec and back.

There are no checksums. A flipped bit that keeps the structure intact decodes to wrong values with no error, so wrap the stream in something with a CRC if that matters.

7Prove the round trip, every codec

tsz verify encodes a file under every codec, decodes it, and compares each value bit for bit. It exits 1 on any mismatch. The test suite does the same on series built to break float handling.

  • Every NaN class with random payloads, both zeros, both infinities, subnormals and the extremes, next to every other.
  • Timestamps that are regular, jittered, backwards, duplicated, random, or i64::MIN and MAX; lengths of 0, 1, 2 and a block plus or minus one.
  • cargo test runs 20,000 random series. The soak in CI runs a million, and checks on each that auto is no bigger than the best fixed codec.

    The suite, and what CI adds

    cargo test, warm, twice in a row on this machine:

    11.9 s13.4 s

    Most of it is the 20,000 random series. CI runs the suite on Rust 1.74 and stable, rustfmt and clippy with warnings as errors, the million-series soak, two minutes of each fuzz target, and the size chart check.

    A two-minute fuzz run of decode here made 13.1 million attempts and found nothing.

    21 tests, and one long one

    Counted with cargo test --locked, as CI runs it: 21 passing across unit tests, three integration files and one doc test. The soak is a 22nd test, ignored by default and run with make soak; it passed here too.

      Weighted toward breaking it

      • Round trips: seeded generators for adversarial series, every codec, bit for bit; every special value next to every other; block boundaries; a streaming encoder that must write the same bytes as encode.
      • The format: FNV hashes of the exact bytes each codec writes for a fixed series, so a format change can't slip in, and the papers' bit costs for a constant series and a regular clock.
      • Untrusted input: every truncation, flipped bits, random bytes, and framing errors that name the problem.
      • The CLI as a user runs it: exact bits through text, stdin and stdout, errors that name the line, and decode | head exiting quietly instead of panicking.

      While building it, nine bugs were planted by hand, one at a time, and the README records that eight made the suite fail. The ninth turned out to change no output at all.

      Deliberately missing

      Checksums
      A flipped bit inside a payload can decode to wrong values without an error, as stage 6 shows. Wrap the stream in something with a CRC if that matters.
      An index
      Blocks are independent, but finding the block for a time range means walking the framing from the start.
      Exceptions in the decimal codec
      One value that isn't n / 10d sends the whole block to a float codec.
      Other shapes and lossy modes
      One series of (i64, f64): no integer or string values, no columns or tags. Nothing rounds, quantizes or drops points.
      crates.io
      The package is tsz-codec and lives on GitHub. tsz on crates.io is the older Gorilla crate it is compared with.

      Run it

      git clone https://github.com/ahmed-hashim-pro/tsz.git && cd tsz
cargo build --release
export PATH=$PWD/target/release:$PATH

gunzip -k data/*.csv.gz
tsz compare data/*.csv
tsz encode data/uci-power-active-2007.csv -o power.tsz
tsz inspect power.tsz
tsz decode power.tsz | head -3
tsz verify data/*.csv

# The suite, then the soak and the size check CI adds.
cargo test
make soak bench-sizes
