rag-knowledge-agent

A command-line agent that answers questions about a folder of documents. It cites every claim, and when nothing in the documents supports an answer, it refuses without calling the model.

Retrieval demos are easy. What decides whether one can face users is what it does when retrieval goes badly, so this one is built around three rules: it has to be able to say no, every claim has to be traceable, and retrieved text is never treated as an instruction.

1Chunk along the headings

A chunk is the unit of citation, so its boundaries decide how precise a citation can be. Each document is split by section first and packed second, so every chunk belongs to exactly one heading path.

  • About 500 estimated tokens per chunk, with a 50-token overlap made of whole paragraphs, never half sentences.
  • Fenced code blocks stay whole: a # comment inside a shell snippet is not a heading.
  • Each file's SHA-256 is stored with its chunks, so running ingest again skips files that have not changed.
  • Token counts are estimated as characters divided by four. A real tokenizer call would make indexing need an API key.

2Index every chunk twice

Every chunk is embedded locally and also written to a BM25 index, so retrieval can match meaning and exact words. Indexing costs nothing, needs no key, and the documents never leave the machine.

  • Dense: all-MiniLM-L6-v2 through sentence-transformers on the CPU, 384 dimensions, stored in ChromaDB.
  • Cosine distance is set explicitly. If ChromaDB ever fell back to L2, scores would go negative and the floor would invert without an error, so a test asserts the metric.
  • Lexical: BM25 with k1 1.5 and b 0.75, 775 terms in 25 KB of JSON, fingerprinted so a stale index is rebuilt instead of trusted.

The trade is a 1.3 GB install, mostly PyTorch, for an index that works offline after the first run.

3Search both ways, fuse the ranks

At question time both retrievers run, and reciprocal rank fusion merges their lists by Σ 1/(60 + rank). It works on ranks because cosine similarity and BM25 scores share no scale.

Fusion decides the order but never the gate. The confidence floor is applied to the best score any single retriever gave a chunk, so the calibration behind the refusal stays valid.

Fusion also keeps each retriever's top hit. Without that, the best semantic match for one probe question fell out of the top five, its support dropped from 0.545 to 0.341, and an answerable question became a refusal. A regression test pins it.

4Refuse before calling the model

If no retrieved chunk reaches a support score of 0.35, the agent prints a fixed refusal and never calls the API. The refusal is deterministic, costs nothing, and works on a clone with no key at all.

The floor was measured, not guessed: 19 probe questions, 12 that the documents answer and 7 that they don't. Switch the retrieval mode to see why hybrid is the default.

Nothing in the corpus covers expenses, so this question stops at the line. The note explaining why goes to stderr, keeping stdout clean:

5Wrap retrieved text as data

The documents are untrusted input. One that says “ignore your instructions” is something the agent may be asked to summarise, and must never obey. Three layers, all in code:

  • Envelope: each chunk goes inside a <document> element with its source, heading and score, and the attribute values are escaped so a crafted file path cannot inject an attribute.
  • Escape: a literal </document> inside chunk text becomes <\/document>, so a document cannot close its own envelope. A test asserts exactly one closing tag survives.
  • Order: documents first, question last, so the last thing the model reads is the trusted instruction.

This limits the damage rather than removing it. The agent has no tools, no network access and no side effects, so the worst a persuasive passage can cause is a wrong answer.

6Validate before printing

claude-sonnet-4-6 doesn't support the API's constrained JSON output, so --json mode asks for JSON and checks it: strip any code fence, parse, then validate against a Pydantic model, all before anything is printed.

  • One retry on failure, carrying the error back. A second failure exits non-zero instead of printing something a caller might parse.
  • The retry replays the bad reply mid-conversation, never as the last turn: a trailing assistant turn is a prefill, and this model rejects it with a 400.
  • Citation scores come from retrieval, never from the model. A model cannot know a cosine similarity, so asking for one invites a confident fabrication.

How long it keeps working

A Meridian-3 continues executing its buffered task queue for up to 12 minutes after losing its network link — this is the offline autonomy window, fixed in firmware and not configurable. [sample_corpus/product-specs.md:… > Offline Autonomy]

The telemetry field to watch

The field offline_seconds counts up from the moment of the last successful report. Watch this value against the 12-minute window; when it crosses that threshold, a safe-park has almost certainly occurred. [sample_corpus/api-reference.md:… > GET /robots/{robot_id}/telemetry]

What happens when the window expires

At the end of the 12-minute window — or sooner if the buffered queue is exhausted — the robot performs a safe-park: it finishes its current motion segment, pulls out of travel lanes to the nearest designated safe-park zone, sets its status beacon to amber, and holds position until the link is restored. It does not accept new tasks and does not attempt to return to a dock, because dock assignment requires Fleet Control. [sample_corpus/product-specs.md:… > Offline Autonomy]

Once the link returns, the robot resumes on its own. You will receive a robot.link_restored event followed by a robot.safe_parked event, and the beacon will read amber until it is acknowledged. No manual intervention is required unless the beacon stays amber for more than a minute after reconnect. [sample_corpus/faq.md:… > What happens during a network outage?]

Measured, not assumed

Hybrid retrieval shipped because of a measurement, not because of the argument that motivated building it. Every number here can be reproduced offline with scripts/calibrate.py.

What it bought

The gap between the weakest answerable question and the strongest unanswerable one is the gate's whole safety budget.

Vector+0.021
Hybrid+0.096

About 4.5 times wider, with the same error counts: 1 of 7 false accepts, 0 of 12 false refusals.

What it cost

BM25 gives partial credit for ordinary shared words, so unanswerable questions creep toward the floor.

Expenses, vector0.130
Expenses, hybrid0.271
Dress code, vector0.147
Dress code, hybrid0.293

Both are still refused, but the distance to the floor shrank from about 0.22 to about 0.06. That is why calibration is a checked-in script, not a one-off.

What didn't go as predicted

The roadmap said hybrid would fix exact-token lookups such as error codes and field names. Measured on this corpus, vector search already found all ten.

Vector 10 of 10BM25 10 of 10Hybrid 10 of 10

With 44 chunks there is little for an embedding to confuse. Hybrid earned its default on the gate margin instead, and the design notes say so plainly.

109 tests, none needs an API key

The Anthropic client is stubbed everywhere. A stub that records zero calls is itself the assertion that the confidence gate never reaches the network.

    Weighted toward what breaks quietly

    • Chunking: heading hierarchies, code fences, size targets, overlap and oversized paragraphs.
    • Ingestion: idempotency, change detection, stale-chunk replacement, PDF pages, and source labels that never leak an absolute path.
    • Retrieval: the collection really is cosine, identical text scores 1.0, the floor, envelope escaping and the context budget.
    • Lexical search and fusion: code identifiers and error codes, a corrupt index treated as a cache miss, fingerprint invalidation, and the anchoring property.
    • Generation: schema validation, the single retry, dropped citations, where scores come from, zero tokens spent by the gate, and no request ending on an assistant turn.

    Two embedders on purpose: a deterministic hashing embedder for bookkeeping tests, and the real MiniLM model for relevance tests, because a fake embedder cannot show that relevant text outranks irrelevant text.

    CI runs ruff, pytest and the keyless quickstart on Python 3.11 and 3.12.

    Deliberately missing

    A re-ranker
    A cross-encoder would separate the topically close questions that still pass the floor. It is the first thing to add.
    Pruning deleted files
    A removed document keeps its chunks until the index is rebuilt. The honest workaround is rm -rf chroma_db && rag ingest.
    Stemming
    BM25 treats “charging” and “charge” as different terms.
    A full eval harness
    The calibration script makes retrieval measurements reproducible, but nothing fails CI when the separation shrinks, and citation accuracy isn't measured yet.
