Mushaf

A Quran reader for the web that shows the printed Mushaf itself: 604 page images, every ayah on them tappable, and pages that turn like a book.

A printed Mushaf is read by the page, so the reader shows the page by default rather than reflowed text, and does the work around it. It knows where every ayah sits on each image, turns pages without losing your place, and checks what is already in the browser before asking anyone else.

1Find the page

Every way into the reader ends at the same address, /tabs/mushaf/page/n, with n from 1 to 604. The index, the search results, bookmarks and shared links all resolve to a page number first.

  • The juz list is a table of start pages that ships with the app, so opening a juz needs no request.
  • Ayah search is the one way in that needs a request: it asks alquran.cloud, then looks up the exact page of each of the first 30 matches. The one you pick opens with that ayah highlighted.
  • Jump to page accepts 1 to 604. Anything else closes the dialog and leaves you where you were.
  • The server names each page before it reaches the browser, from the same bundled geometry, and sets the link preview image to that page.

2Know where every ayah sits

The page is a picture, so the reader carries a map of it: one box per ayah per line, in the image's own 1260 px coordinates. The map loads once, when you first open a page in image view, and is used every time you tap.

  • A tap is scaled into page coordinates, then tested against the boxes. Inside a box wins. Otherwise the nearest box wins, but only within 50 px of the 1260 px page, about 13 px on screen when the page is drawn 330 px wide.
  • An ayah that runs over several lines has a box on each, and all of them light up together.
  • Highlights are placed as percentages of the image, so they stay on the ayah at any zoom from 50 to 200 percent and on any screen. Recitation and search results use the same boxes.

Ayah keys like 1:7 stand in for the text here; the real page image carries the words.

3Turn the page like a book

On a wide screen the reader shows two pages at once, paired as in print: the odd page on the right, the even page on the left. Open an even page and its odd partner becomes the main page.

  • In two-page view of the page images, a turn is a 3D curl in six segments. The free edge leads while you drag, the spine takes just over half the final rotation so the whole sheet ends past vertical, and the turn commits past 60 degrees or springs back.
  • A button turn runs the full half circle in 500 ms with ease-in-out; a release finishes the rest of the way in proportion, never under 200 ms.
  • The address updates with replaceState, so turning pages adds no history entries and the URL always points at the page on screen.
  • In single-page view, a swipe needs more than 50 px of travel and 1.5 times more sideways than vertical movement, and the current page stays on screen until the next page's text has arrived.

4Check this browser first

Before a text request leaves the browser, the reader's service worker looks in its own cache. A reply it already holds is served from there, with no network at all. Only a miss goes out to alquran.cloud.

  • The rule is performance: a cached reply up to 30 days old wins. Older ones are dropped and fetched again.
  • It keeps the 100 most recently used replies. When a new one arrives with the cache full, the least recently used goes. Search, translation and tafseer replies share those 100 places.
  • The worker is installed during the first visit, so requests made before it takes over go straight to the network.
  • Page images are not in this cache. They come from quran.com's CDN, which marks them cacheable for about 296 days, so the browser's own cache can answer repeats.

5Fetch the text, one page at a time

One request per page, for the Uthmani text of exactly the ayahs on it. In two-page view, a second request fetches the facing page.

  • The reply carries ten fields per ayah. The reader keeps five: its number, its number in the surah, the juz, the surah, and the text, which feeds copy, share and the text views.
  • Its page boundaries agree with the bundled geometry: the same ayahs, page for page, on all six pages sampled.
  • If the request fails in image view, the reader still shows the page image and raises no error. In the text views it says so, with a retry button.

6Draw the printed page

The page image is the default view: page001.png to page604.png, 1260 px wide, from quran.com's CDN, which serves them from its Hafs Madani set. The ayah boxes from stage 2 sit on top as highlights.

  • Opened on a screen 1024 px or wider, the reader starts in two-page view unless you have chosen a view yourself. The check runs when the reader opens, not on every resize.
  • At 768 px wide and below, the zoom and two-page buttons are hidden and the page fits the screen.
  • The stacked page edges beside a spread thin out near the covers: one edge line per page still to come on that side, up to three.

What the server sends

The page list is prerendered. Each page is rendered on the server when asked, so a shared link arrives titled, with its own preview image.

Index: prerenderedPage: server-rendered

A rendered page is about 40.5 kB of HTML. If server rendering takes over 10 seconds, the server sends the client-rendered shell instead.

Deliberately missing

Zoom and two-page view on phones
Their buttons are hidden at 768 px wide and below.
Swipes in some places
Ignored within 20 px of the screen edge, which belongs to the iOS back gesture, and while the page is zoomed in.
An unbounded text cache
The last 100 replies, up to 30 days old, and no more.
Long search result lists
The first 30 matches, each needing its own page lookup.

Try it

  • Open the index of surahs and juz at mushaf.geohashim.com/tabs/mushaf.
  • Go straight to any page: /tabs/mushaf/page/1 to /tabs/mushaf/page/604.
  • On a screen 1024 px or wider, pages open as a two-page spread. Drag across it to turn the page.
  • Tap an ayah on the page to play, copy, share, bookmark, translate it or read its tafseer.

A first visit starts with a short welcome screen.
